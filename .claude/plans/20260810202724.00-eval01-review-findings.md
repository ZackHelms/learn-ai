## Headline: the "high effort collapses" signal was mostly a scorer artifact

The early signal (sonnet medium 96.4 beating high/xhigh/max by ~20, det half
collapsing at high+ effort) does not survive scrutiny. Three bugs in
`eval_ashfall.py`'s runtime pass, all found by manually reproducing failing
checks (source: driven in Playwright this session, per-candidate proof below):

1. **Dev-tab discovery was anchored.** `find_button_in_tabs` only tried
   `^dev\w*$`, `^debug$`, `^tests?$` to open a hidden dev area. Higher-effort
   candidates build tabbed UIs labeled "6 Dev", "Dev Panel", "6. Dev", "Dev 6"
   - none match. Result: C1_runtime/C2/C3/D2/D3 (20 pts) zeroed as a cluster
   for 9 of 20 set1 candidates whose panels worked fine when opened by their
   real label. The docstring promised a walk-all-tabs fallback that was never
   implemented. Haiku "won" these checks by building flat UIs with every
   button visible - the eval was partly measuring UI simplicity, not
   correctness.
2. **"N passed, 0 failed" counted as a failure.** The fallback counter matched
   the word "failed" in zero-failure summary lines, so C3 (6 pts) zeroed for
   candidates that passed every one of their own tests (r11, s11, s15, t12,
   t14, t15, u11, u12 print this style).
3. **Hash extraction grabbed prose.** `hash\W{0,12}(\w+)` took the first word
   after "hash", so t14's "Hash Current State" button yielded hash="Current"
   and a benchmark still printing "running" yielded hash="running" - making
   the D3 determinism comparison vacuously true ('Current'=='Current').
   Points happened to be right; the verification was not real. Second layer of
   the same bug: preferring the FIRST digit-bearing token still picked t14's
   static "Current state hash: 104c3359" (identical across reloads no matter
   what the benchmark does) over its "FINAL STATE HASH : c13e0b3e" printed
   below - so extraction takes the LAST digit-bearing match, since benchmark
   output is appended after any static labels.

All three are fixed in `eval_ashfall.py` (word-boundary + bounded
short-label tab walk; explicit "N passed, M failed" parsing; last
digit-bearing hash match + polling for slow benchmarks). All 26 candidates (set1 +
legacy r01-r05/t04) re-scored; only the affected checks moved (verified by
per-check diff vs git HEAD). AI halves untouched.

## The new story the corrected numbers tell

- Sonnet, opus, and fable essentially saturate eval01: 90-100 everywhere
  except u13 (real bug). Five candidates hit 100.0. Haiku sits at 73-82.
- Effort level barely matters above haiku on this task; what separates
  frontier rows is single real defects (a failing invariant test, a blocking
  overlay), not capability tiers.
- The AI-judged half saturates harder: 46/46 (max) for nearly every sonnet+
  candidate, all five gradings identical. It currently differentiates nothing
  above haiku (data: listscore across s/t/u).
- Cost still scales with effort: sonnet low $1.10 -> fable max $17.70 for at
  most ~1 point of total. Inference: on this task, low effort on a
  frontier model is the efficiency frontier; "medium beats max" is dead, but
  "low is all you need" survives, which is itself a finding about effort
  calibration.

## Agenda verdicts

1. **Prompt: freeze it** (as leaned). No edits for set2; comparability wins.
   But note the ceiling: eval01 can no longer rank sonnet vs opus vs fable.
   If ranking frontier models becomes a goal, that is eval02 (harder task or
   deeper det checks), forked, not edited.
2. **RUBRIC: freeze for set2.** The det half's trap coverage is fair (it
   caught real defects once the scorer stopped lying). The real gap is the AI
   half's ceiling, not its precision: F/G items are 0/1/2-coarse and every
   strong candidate maxes all of them. For eval02 consider anchored 0-5
   scales, pairwise comparison, or added judged dimensions (UX polish, code
   quality) - a grader version bump + full re-grade if ever applied to eval01.
3. **Grader variance: acceptable, keep 5 gradings.** Per-candidate ai spread
   (max-min): r11 6, r14 5, r12/r13 3, s12/s14 4, everything else 0-2 (zero
   for nearly all t/u rows - trivially, at ceiling). The ~4-point threshold is
   breached only on haiku-tier candidates, where averaging 5 is doing its job.
   Not worth re-grading s1x to purge the plan-mode mixture: gradings are
   pinned at/near ceiling regardless of framing (46 +/- 1), and set2 will be
   uniformly clean anyway.
4. **Provenance ledger: resolved.** Set1 is all bare via generate.sh; the
   9Aug context-biased rows (r01-r05, t04) stay as the separate contrast
   table, now re-scored with the same fixed scorer so det halves are
   comparable. Context impact on haiku low: r01 70.8 vs r11 81.6 - noisy,
   inconclusive; t04 vs t14 both 100.0.
5. **Det-scorer robustness: was THE problem; fixed and verified.** New rule
   for the template: a deterministic check that fails must be reproduced by
   hand before it is trusted - scorer discovery bugs look exactly like
   candidate failures in aggregate numbers. Known remaining limits, accepted:
   console-only test output scores 0 (arguably correct per prompt), digitless
   hex hashes (e.g. "deadbeef") fall back to first-match, tab walk is capped
   at 12 clicks.
6. **Budget (source: RESULTS.md gen sidecars; grading est from prior
   session).** Set1 generation: haiku $0.79, sonnet $26.51, opus $39.64,
   fable $50.60 = $117.55; grading ~$1 x 5 x 26 candidates ~= $130 est
   (grade.sh does not record per-session cost - worth capturing in the
   .ai.json sidecar for set2). A full identical set2 ~= $220-250 and ~6h of
   generation wall time serialized (fable alone ~1h via zrunall).
7. **Template extraction: pending, now better informed.** Additions for the
   writeup beyond the agenda's list: (a) manual-reproduction rule from
   verdict 5; (b) check the judge half for ceiling saturation before trusting
   its rankings; (c) user-like click semantics (Playwright) catch real UX
   bugs that DOM inspection would miss (u13's overlay); (d) prefer
   auto-retrying locators over stored element handles when pages re-render
   every tick; (e) discovery heuristics must be tested against candidates
   that PASS and candidates that FAIL - set1's haiku-passes/sonnet-fails
   pattern was the tell that discovery, not capability, was being measured.
   Candidate home unchanged: eval01/README.md section or TEMPLATE.md.
