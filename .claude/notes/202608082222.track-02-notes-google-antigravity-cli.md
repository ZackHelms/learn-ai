## Finding 1: the free Gemini developer tier was withdrawn

Starting 2026-06-18, Gemini Code Assist IDE extensions and Gemini CLI stopped serving
requests for the Code Assist for individuals, Google AI Pro, and Google AI Ultra tiers.
The "Login with Google" option was removed. Migration path is the Antigravity family.

source: <https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals>
(page last updated 2026-06-23, checked 2026-08-08)

Consequence for this track: any guide describing a free Gemini CLI is stale. The free
Google terminal story is now Antigravity CLI (`agy`).

## Finding 2: docs disagree with the installer

The install page documents `--skip-aliases` and `--skip-path` flags. The Linux install
script's argument parser accepts only `-d/--dir` and `-h/--help`, and aborts on anything
else:

```bash
*) echo "[ERROR] Unknown parameter: $1" >&2; show_usage; exit 1 ;;
```

So on Linux there is no supported way to opt out of the shell-environment step.
inferred: those flags belong to the Windows installer or an older revision.

source: <https://antigravity.google/docs/cli/install> (checked 2026-08-08)

## Finding 3: install behavior

Installer verifies a SHA512 checksum from a manifest before writing the binary. Manifest
and binary come from the same origin, so this protects against corruption and transport
tampering, not against a compromised origin. It is a checksum, not a signature.

The script itself does not modify shell profiles. It delegates to `"$BINARY_PATH" install`,
and that step does. Observed result: the same `export PATH` line appended to BOTH
`~/.bashrc` and `~/.profile`.

This was redundant. `~/.local/bin` was already on PATH by two independent mechanisms
(Ubuntu's stock `~/.profile` block, plus an existing export in `~/.bashrc`). The installer
logged "PATH verification: ~/.local/bin is correctly configured in active PATH environment"
and appended anyway. Active PATH ended up carrying the directory three times.

The binary self-updates in the background during normal runs, so any version recorded
here is a snapshot, not a pin.

**Cosmetic bug worth warning readers about:** all install log lines are prefixed `ERROR:`
even though the severity codes are `I` (Info). The binary logs before `google.Init()` runs.
Nothing failed. A beginner will reasonably think the install broke.

## Finding 4: authentication under WSL2 works, via the manual URL loop

Prediction going in was that browser launch would fail and hang. It did not.

The CLI printed an OAuth URL, which ctrl+click opened in Windows Chrome. Google returned a
code, pasted back into the CLI. This is the flow the docs describe for SSH sessions, not
local ones.

Login method picker offers Google OAuth or "Use a Google Cloud project". OAuth with a
personal account is the free path. The Cloud project option implies a billed GCP project
and is out of scope for a strictly-free track.

**Session persistence is file-based, not keyring-based.** Despite no Secret Service
provider on the box, relaunching `agy` signed in silently. `~/.gemini/config/config.json`
grew from 79 to 183 bytes, mode `0600`. inferred: the token lives on disk protected by
file permissions. This is what makes WSL2 work; it is also a weaker posture than the docs'
keyring description implies.

## Finding 5: telemetry defaults to ON

The onboarding consent checkbox for sharing interaction data with Google is pre-checked.
Clearing it requires pressing space. Verified afterward in `/settings`:
`Enable Telemetry: off`.

For a track aimed at people who will not pay, this belongs as an explicit numbered step,
not a footnote.

## Finding 6: quota is two pools, and the limit is undisclosed

`/usage` reports two independent weekly pools:

- Gemini models (Flash, Pro)
- Claude and GPT models (Opus, Sonnet, GPT-OSS)

Burning one does not touch the other. On-screen explanation: quota is consumed
proportionally to token cost, so cheaper models and shorter tasks last longer.

**No absolute number is exposed anywhere.** Not on the pricing page, not in the CLI. Only
percent-remaining. The honest statement for this repo is that Google publishes no free-tier
quota figure; only relative burn-down is observable.

The in-product name is "Antigravity Starter Quota". The pricing page calls the same thing
"For Individuals". Searching docs for one name will not find the other.

source: <https://antigravity.google/pricing> (checked 2026-08-08)

### Measured burn

| Action | Model / effort | Quota before | Quota after | Delta |
|---|---|---|---|---|
| "what is your model name and version?" | Gemini 3.6 Flash, high | 98.80% | 98.05% | -0.75% |

One trivial question, one-sentence answer. Extrapolated naively that is roughly 130 such
prompts per week.

Caveats that must ship with this number: burn is proportional to token cost, so a trivial
prompt is not representative of real work; `high` was the default effort and `low` is
available; single observation, single account, single day.

## Finding 7: the pricing page trails the product

The pricing page lists Gemini 3.5 Flash, 3.1 Pro, and 3 Flash among free agent models.
The CLI defaulted to Gemini 3.6 Flash, which is not on that list.

`/models` on Starter Quota offered:

- Gemini 3.6 Flash (effort: low, medium, high - default high)
- Gemini 3.5 Flash (effort: low default, medium, high)
- Gemini 3.1 Pro (effort: low default, high)
- Claude Sonnet 4.6 (Thinking)
- Claude Opus 4.6 (Thinking)
- GPT-OSS 120B (Medium)

**This is the sharpest cross-provider finding so far.** Anthropic sells no free terminal
agent - Claude Code requires a paid plan. Yet Claude Opus is reachable in a terminal for
$0 by signing into Google. The story is not that one vendor is stingy; it is that
first-party free developer tooling is contracting while model access gets resold through
competitors' free tiers.

source for the Claude Code requirement: <https://code.claude.com/docs/en/setup> (checked 2026-08-08)

## Finding 8: no accidental spend

`/credits` reports "AI Credits not enabled". `/settings` shows `Use AI Credits: off`.
Paid top-ups are opt-in. Readers should be told to leave it off and told where it lives.

## Finding 9: it occupies Gemini CLI's config directory

`/agents` reports the global agent path as `~/.gemini/config/agents/{agent_name}/agent.md`,
not an Antigravity-specific location. `~/.antigravity` and `~/.config/antigravity` do not
exist. A `.migrated` marker file is present.

Workspace-level agents live at `.agents/agents/{agent_name}/agent.md`, which is a different
convention from `.claude/agents/*.md`.
